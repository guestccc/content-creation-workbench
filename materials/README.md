# materials —— 素材与产物目录

这个目录是工作台的**素材仓库**：原片从这里进，切好的片段、字幕、成片从这里出。
目录名用英文，是为了在任何终端、脚本、命令里都不用转义。

## 目录规划

按**流程分段**，每一段只放一类东西：

```
materials/
├── source/     ① 原始素材：待切的视频往这里拷
├── clips/      ② 镜头分割产物：每条原片一个 <视频名>_scenes/ 子目录
├── subtitle/   ③ 字幕提取产物：每条视频一个 <视频名>.srt
├── crawl/      ④ 素材抓取产物：每次任务一个 job_<id>/ 子目录（小红书图文）
├── finalcut/   ⑤ 一键成品产物：每次合成一个 finalcut-<时间戳>/ 子目录
├── dubbing/    ⑥ 智能配音产物：每次生成一份 <名字>.wav
└── output/     ⑦ 成片，待发布
```

| 分段 | 放什么 | 谁写进来的 |
|---|---|---|
| `source/` | 从相机、手机、剪辑软件导出的原片 | **你自己拷**。镜头分割页打开时，输入目录默认就停在这里 |
| `clips/` | 切好的单镜头片段 | 后端。每条原片单独建 `<视频名>_scenes/` 子目录，重名时追加 `-2`、`-3` |
| `subtitle/` | 识别出的字幕（.srt） | 后端。字幕提取页逐条视频转写（VideoCaptioner），重名时追加 `-2`、`-3` |
| `crawl/` | 从小红书等平台抓来的图文素材 | 后端。素材抓取页每次任务建 `job_<id>/` 子目录 |
| `finalcut/` | 一键成品：成片 + 逐字稿 + 过程产物 | 后端。一键成品页每次合成建 `finalcut-<时间戳>/` 子目录 |
| `dubbing/` | 智能配音产物（.wav 等音频） | 后端。智能配音页每次生成一份 `<名字>.wav`，重名时追加 `-2`、`-3` |
| `output/` | 拼好待发布的成片 | 后续的合成/导出流程 |

**根目录本身不放东西。** 原片进 `source/`，产物进各自的分段目录 —— 这样
「哪些是素材、哪些是产物」一眼可辨，也不会几百个文件糊在一层。

## 什么入库、什么不入库

**入库的只有骨架与这份说明**：

- 入库：本文件（`materials/README.md`）和各分段的 `.gitkeep` 占位文件。
  git 不跟踪空目录，没有占位文件，新克隆下来就只剩一个空文件夹。
- 不入库：其余一切。原片动辄几百 MB 到几 GB，切分产物更是成倍增长，
  提交上去仓库就没法用了。

规则见根目录 `.gitignore`（先 `materials/**` 全挡，再逐个放行上面这几项）。

> 别人克隆仓库后拿到的是一套空的骨架，不含你的任何素材 —— 这是刻意的。

## 目录不见了怎么办

不用手动建。后端每次启动都会按 `backend/app/core/materials.py` 里的规划把
骨架补出来（有人删了目录、或者把 `SCENE_MATERIALS_DIR` 指到了别处，都会补齐）。

## 想放到别处

素材动辄几十 GB，放在系统盘上不合适时，在 `backend/.env` 里改：

```bash
SCENE_MATERIALS_DIR=/Volumes/素材盘/workbench-materials
```

支持 `~` 开头。指到哪儿，`source` / `clips` / `subtitle` / `crawl` / `finalcut` /
`dubbing` / `output` 就建在哪儿，页面的默认输入/输出目录也跟着走。
