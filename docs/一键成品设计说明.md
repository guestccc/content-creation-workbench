# 一键成品（finalcut）设计说明

这份文档说明工作台「一键成品」功能背后的设计：文案怎么按视频时长与口播语速
定量、为什么上屏用 ffmpeg `drawtext` 而不是 ASS、Windows 中文路径的滤镜转义
问题怎么绕、框选坐标怎么从前端一路传到烧字命令、以及文案任务为什么没有
进程回收。

**页面上只剩「生成文案」两件事**（选素材 → 出文案）：文案生成完，用户复制出去
在剪映里配音、人工烧字 —— 烧录合成（框选、样式、出成片）已从**页面**摘掉，
后端接口 / 表 / 服务 / 测试全部保留（§2–§4、§6、§7 讲的就是这套仍然存在的
实现，恢复入口即可用）。本文是当你想知道「为什么这么设计」时的参考。

> 实现位置：后端 `backend/app/services/finalcut_*.py`（环境 / 文案 / 排版 /
> 两个 runner）、`backend/app/api/v1/finalcut_jobs.py`，前端
> `frontend/src/pages/FinalCut/`。

---

## 1. 功能全貌：两步流程

```
① 选素材                      ② AI 文案
字幕：历史产物 / 本地 .srt      左列：原始字幕（字幕原文 / AI 输入的素材）
成片：历史成片 / 本地 .mp4      右列：字幕素材拆解：主题/受众/卖点/调性
（成片的 ffprobe 时长是        「这条视频几点几秒，按 N 字/秒算，每条文案 A–B 字」
  文案字数预算的依据）          多条候选：一条一个 Tab，切着看 + 复制按钮
                               面板里是文案(可编辑) + 实时「约念几秒 · N 字」+
                               为什么 / 好在哪 / 逐段拆解
```

**到这里就结束了**：文案只有一份，既拿去剪映生成配音，也拿去人工烧字。
原先的第 ③ 步（框选与合成）已从页面摘掉，后端接口保留。

第 ② 步左右分栏是**为了对照**：左边是 AI 读到的素材，右边是它写出来的文案 ——
不然分不清「没读懂素材」和「读懂了但写得差」。左列的字幕来自
`GET /finalcut/copy-jobs/{id}/subtitle-text`（原文 + 素材两个视图），
**与任务状态无关**：排队中、失败、取消时都给，失败时恰恰最需要看 AI 读到了什么。

两个任务域对应两张表：

- **文案任务 `FinalcutCopyJob`**：读字幕 → 调 AI（DeepSeek，OpenAI 兼容接口）
  → 解析 JSON 落库。没有子进程、没有磁盘产物 —— 删除只删记录，删除确认框
  也不带「连同产物一起删」的勾选。
- **合成任务 `FinalcutRenderJob` + `FinalcutRenderItem`**（页面已无入口）：
  每条文案一个 item、一个成片。有 `child_pid`、有输出目录，删除确认框带
  purge 勾选（勾了整棵删输出目录）—— 与混剪同一套规矩。

但只起**一个 worker 线程**（`FinalcutJobWorker`）：每轮先抢 pending 文案任务
（快、秒级），再抢 pending 合成任务。与混剪一样的串行语义；代价是长合成
会挡住新文案任务，进度在页面上可见，可接受。

## 2. 为什么用 drawtext 而不是 libass/ASS

> 本节与 §3、§4、§6、§7 讲的都是**烧录**那条链路。它已从页面下线（改为人工
> 在剪映烧字），**后端代码与本文内容原样保留** —— 恢复页面入口即可用。

本机 ffmpeg（gyan.dev essentials）`drawtext`/`subtitles`/`ass` 都在。选
drawtext 不是 ASS 不可用，而是它**确定**：

- 直接吃**字体文件路径**，不经过 fontconfig 的字体名解析 —— 同名多 face、
  `.ttc` 取第几个 face、机器上装了别的中文字体导致的匹配漂移，都不再是
  变量；
- 样式只需要「颜色/描边/底框/字号/位置」五个维度，ASS 的协作成本
  （生成 .ass 文件、样式段、换行语义）在这个阶段是浪费。

代价是排版要自己估算（见 §4）。`subtitles`/`ass` 留作日后做描边动画、
逐字效果的升级路径。

## 3. Windows 路径转义：临时目录 + ASCII 相对名 + cwd

drawtext 的 `fontfile`/`textfile` 参数直接进滤镜串，Windows 路径里的
盘符 `:` 与 `\` 在滤镜语法里都是特殊字符，转义规则又绕又脆（本仓库路径
还含中文，已经踩过坑）。绕法与混剪的 concat list 一脉相承：

1. 跑任务时把字体复制成 `<任务临时目录>/font.ttf`，把预折行的文案写成
   `<任务临时目录>/copy.txt`（**UTF-8 无 BOM** —— 带 BOM 在部分构建上
   渲染成方框，有单测断言首字节）；
2. 滤镜串里只有 `fontfile=font.ttf:textfile=copy.txt` 两个 ASCII 相对名；
3. ffmpeg 以 `cwd=<任务临时目录>` 启动 —— `fontfile`/`textfile` 是普通
   fopen，按进程 cwd 解析。`-i`、输出、`-progress`、日志仍走绝对路径。

单测断言任何样式的滤镜串里都不出现 `\` 与盘符（`[A-Za-z]:[\\/]`）。

还差一步：drawtext 默认对 **textfile 的内容也做 `%{...}` 展开**，而广告
文案里出现裸 `%`（「立减100%」）是常态 —— 真机上这样的文案只 warning 一句
`Stray %` 就把**整条文案渲成空白**（第一版踩了这个坑，成片里字都没了）。
滤镜串固定带 `expansion=none`，`%` `{` `}` 全部按字面量处理。

临时目录是 `materials/finalcut/.tmp/finalcut_<job_id>/`，成功/取消后整棵
删掉，失败时留下 `ffmpeg_item_XX.log` 供排查。输出先写 `.partial.mp4`
再改名 —— 半成品永不以成片名出现。

## 4. 排版：估算决定字号与换行，居中交给 ffmpeg 实测值

分工是这样：

- **Python 侧只决定「字号与换行点」**（`finalcut_render.py`）：按估算字宽
  贪心折行（CJK/全角 ≈ 1.0em，ASCII ≈ 0.55em，`unicodedata.east_asian_width`
  为据），字号从 64 降到 16 逐档试，第一个满足
  `行数×字号 + 行距×(行数-1) ≤ 框高×1.15` 的胜出；降到底仍放不下就截断，
  截断原因写进该条 item 的 `error_message`（任务仍算成功）。
- **居中交给 drawtext 的 `text_w`/`text_h` 实测值**：滤镜串用
  `x=<框中心x>-text_w/2:y=<框中心y>-text_h/2`。估算的误差只表现为向内/向外
  溢出，**不会出现偏右**。

前端框内的实时预览（原 `pages/FinalCut/typography.ts`）是同一套算法的 TS
移植，字号按 overlay 高 / 视频高 等比缩放到 CSS 像素 —— 近似所见即所得，
但 JS 没有 `east_asian_width`，用码点区间近似，是「估算 + 可调」策略的
一部分（字号随时可以手调覆盖）。该文件随框选界面一并从页面删除（见 §1），
前端排版从此只发生在后端。

## 5. AI 文案：按口播语速定量，坏了就明说

### 定量：文案是口播稿，要念满整个视频

**文案的用途决定了它的长度模型**：它只有一份，用户在剪映里选一个音色生成
配音，同时在画面上人工烧字。所以「写多少字」的正确问法是「念满这段视频需要
多少字」，不是「观众几秒读得完多少字」。

```
target = 视频时长(秒) × 口播语速(字/秒)
预算   = [target × 0.9, target × 1.1]        # ±10%，咬紧
```

例：36.294 秒的视频、实测语速 5.8 字/秒 → 目标 210 字，预算 189–232 字。
预算由 `char_budget(duration, chars_per_second)` 算，语速是**任务上的快照**
（创建任务时落 `finalcut_copy_jobs.chars_per_second` 列）：请求体带
`chars_per_second` 就用它，不带就用当前全局默认值 `FINALCUT_CHARS_PER_SECOND`
（`backend/.env`，默认 5.0，见下）。快照之后不再回头看全局配置 —— 否则事后
改一次全局值，历史任务的字数预算、页面上的秒数就会与当时生成的内容对不上。

上面这两件事都返工过一轮，理由出自同一个事故：

- **4.5 是错的语义**。它原本按「观众阅读速度」定，实测下来用户那个音色的
  口播速度是 5.8 字/秒 —— 一条按 4.5 写的稿子拿去配音只会念出视频的三分之二，
  后半段没有声音。
- **旧的提示词在自相矛盾**：一边要求「字数必须落在 114–163 字」，一边要求
  「文案分 1-3 行、每行不超过 15 字」（3×15 = 45 字封顶）。模型两头占不住，
  五条候选全写成 78–88 字。现在**总字数是唯一的硬指标**，行数不限，
  「每行 12–25 字」只是排版建议 —— 两者冲突时让位于总字数。

展示给用户的 `char_count` 由解析侧 `count_chars` **实测**（含标点、不含换行）
—— LLM 数不准自己的字数（真机上 92 字的文案回填成 135），采信回填值，
「这条多少字、视频多长，配不配」的核对就成了误导。页面上那条「约念 X 秒」
是拿这个实测字数除以语速实时算的（`pages/FinalCut/copyLength.ts`，与后端
同一套算法；正文可编辑，删两句立刻看得见秒数变化）。

> 旧版本里每条候选还带一个 `target_seconds`，那是模型自己回填、恒等于视频
> 时长的假数字，与它写的字数毫无关系。已删除；老任务的 result 里残留该键
> 会被 pydantic 静默忽略（`CopyCandidate` 没开 `extra='forbid'`），
> 历史任务照常打开，不需要数据库迁移。

### 分段骨架：把「控总量」降成「控四小段」

只给一个总字数，模型写完第一段就凭感觉收尾。所以 user 消息里另给一份骨架，
四段（开头钩子 15% / 痛点或场景 25% / 卖点与证据 37.5% / 价格与行动号召 22.5%），
每段给 ±5% 区间，**各段之和恒落在整体预算内**（有单测钉住）；目标不足 120 字
时改三段 —— 每段只剩十几字的话模型写不出东西。同时另给一个**目标数**（区间
中点）：模型会把区间当上限用，给 189–232 它就写 180 出头。

### 提示词与解析

`build_copy_messages` 要求模型**只输出 JSON**（analysis + copies，每条带
text/angle/char_count/why/highlights/breakdown）。解析侧 `parse_copy_payload`
逐条 pydantic 校验、丢非法条目；0 条有效 → 任务失败。
`extract_json_object` 容错剥 ```json 围栏、取首个 `{` 到最后一个 `}`。
原始响应全文落 `raw_response`，出问题时不用猜 AI 说了什么。

`AI_MAX_TOKENS` 是 8192（原为 4096）：单条 200+ 字、`breakdown.content` 是正文
原文（等于正文输出两遍），90 秒视频 5 条接近 4700 tokens —— 不改会**静默截断
JSON**，报「AI 返回里没有一条可用的文案」。

### 配置与安全

AI 配置（base_url / model / key）与**口播语速**都在同一个弹窗里填、写回
`backend/.env`（照 `subtitle_settings.py` 的原子写 + 段头管理）。

- **key 永不出后端**：读接口只给掩码（`sk-****abcd`），写接口收到 `api_key=""`
  表示保持原值 —— 避免「只想改模型却把 key 抹掉」。
- **语速分两层**：全局值只是**新任务的默认值**（页面上每条任务可单独覆盖 ——
  创建请求体带 `chars_per_second` 即覆盖，快照进任务记录，见上）；全局值的
  写入（`FINALCUT_CHARS_PER_SECOND`，段头「一键成品（口播语速）」）：
  范围 1.0–15.0，越界 400 **且一个字节都不写**（校验前置，先校验再写两处）；
  请求里不带这个字段 = 不改。弹窗里有实测换算助手：填「87 字念了 15 秒」，
  点一下算出 5.8 填进主字段。校验写在写值函数里而不是 pydantic validator ——
  `validate_assignment` 是关的，热同步的 `setattr` 会绕过校验。
  段头标记取「口播语速」而非「一键成品」：`env_file._is_section_header` 是
  **子串匹配**，AI 段头 `# ---------- AI（一键成品的文案生成） ----------`
  含「一键成品」，用了它语速键会被插进 AI 配置段里（有专门的回归用例）。

### 取消的延迟上界

文案任务没有子进程，取消 = 服务层置状态列，runner 在**相位边界**（读完
srt / HTTP 返回 / 解析完）与重试间隙重读状态列并弃结果。在途 HTTP 无法
即时中断，取消延迟上界 = `AI_TIMEOUT_SECONDS`（120s）。启动时
`recover_interrupted_copy_jobs` 把 running 的文案任务标
`failed（服务重启，任务中断）`；合成任务照混剪的 `is_our_child` 核对 +
整组 kill。

## 6. 框选：手势交给库，自己只做坐标换算

前端不手写指针事件（指针捕获、把手命中判定、越界钳制都是高风险低收益）：

- **react-selecto** 负责「在视频上拖出一块区域 = 画新框」（`e.rect` 是
  相对 overlay 的容器坐标）；
- **react-moveable** 负责框的拖动与四角缩放，自带边界钳制与吸附对齐线
  （视频中线 / 四边各一条参考线）。

自己只写一步换算：px → 归一化 0-1（除以 overlay 的 `getBoundingClientRect()`），
另有四个百分比 `InputNumber` 微调兜底。`<video>` 用 `display:block` +
`width:100%`，高度自适应，overlay 与画面区天然重合，没有 letterbox 映射
问题。归一化坐标与分辨率无关，跑任务时乘 `video_spec`（创建任务时固化的
显示尺寸快照，`probe_video_spec` 已在 ±90/270 旋转时交换宽高，ffmpeg
转码默认 autorotate，与浏览器预览闭环）。

moveable 直写 DOM 的 `transform` 不归 React 管，拖动/缩放**结束时**从
`getBoundingClientRect()` 读实测矩形提交，并手动清掉 transform —— 否则
样式 left/top 更新后旧 transform 还叠着，框会跳一下。

## 7. 音频分支：不能无脑 `-c:a copy`

混剪成片一定是 aac，但任意本地 `mkv/mov` 可能带 vorbis/pcm/ac3，塞进 mp4
会让 muxer 报错或产废片。创建任务时 `probe_video_spec` 顺手取
`audio_codec` 落库，烧字时分支：

- `aac/mp3` → `-c:a copy`（流复制）；
- 其它编码 → `-c:a aac -b:a 128k`；
- 无音轨 → `-an`。

统一 `-map 0:v:0 -map 0:a:0?`，把字幕/数据流丢掉。

## 8. 路径安全

- **历史产物**（混剪成片 / 字幕文件）走 `GET /finalcut/sources` 列出，
  路径由后端从任务记录推导，前端只传「选了哪条」；
- 文案任务用的字幕走 `GET /finalcut/copy-jobs/{id}/subtitle-text`：接口只收
  **任务 id**，路径同样由任务记录推导 —— 文案任务既可能用历史产物、也可能用
  任意本地文件，但固化在记录里的只有创建时校验过的那一条；
- **任意本地文件**在**创建任务时**校验：`absolutize_path` + 后缀白名单
  （字幕 `.srt/.ass/.vtt`、视频 `.mp4/.mov/.mkv/.webm`）+ `is_file()` +
  视频须 ffprobe 探得出规格，校验后固化进任务记录，之后只认记录里的路径；
- 第 ① 步要预览任意本地成片（框选界面的画框背景也是它），另有**只读**流式
  端点 `GET /fs/preview?path=`（绝对路径 + 后缀白名单 + `is_file()` + Range）。
  安全边界与 `/fs/list` 同级，前提是「本工具仅监听 127.0.0.1 单机使用」。
  它放在 `/fs` 而不是 `/finalcut`：镜头分割 / 字幕提取的素材列表也要播本地
  视频，三个功能共用一条流（见 `镜头分割设计说明.md` 第 11 节）。

## 9. 已知限制（本版不做）

- 文案**全程显示**，不支持时间段控制（上屏时机不可调）；
- 只支持水平多行文案，不支持竖排、逐字动画；**emoji 会渲染成方框**
  （中文字体里没有 emoji 字形，drawtext 不打 emoji 字体兜底），文案里
  别带 emoji；
- AI 请求发出后不能即时中断（取消只保证「不落库」，上界 120s）；
- **老任务的语速列是 0.0**（语速快照列上线前创建的任务）：当时按全局值跑的、
  具体值不可考，历史列表与详情如实显示「—」。若这种任务恰好在升级时停在
  pending（`recover_interrupted_copy_jobs` 只收拾 running 的，重启后 pending
  照样被认领执行），runner 会回退**当前**全局值算预算 —— 跑出来的预算可能与
  当时排队前页面上显示的略有出入，属可接受的兼容代价；
- **90 秒以上的视频逼近输出上限**：单条 500+ 字 × 5 条 + breakdown 把正文
  输出两遍，即便 `AI_MAX_TOKENS` 已提到 8192 也接近天花板。超长视频建议
  把候选条数调小（`FINALCUT_COPY_COUNT_DEFAULT` / 页面上的条数），
  否则会拿到被截断的 JSON（表现为「AI 返回里没有一条可用的文案」）；
- 文案素材只能来自一个字幕文件（不支持直接粘贴文本、多字幕合并）；
- 第 ② 步左列的素材是**现读现算**的，不是任务执行时的快照：输入可复现
  （不像不可复现的 AI 输出必须存 `raw_response`），现算让排队/失败/取消/历史
  任务都有这份素材；代价是字幕文件在任务跑完后被改写的话，看到的会与当时
  喂给模型的不一致；
- 同一条文案配多个框 = 多个 item = 多个成片，但**不支持一条成片里放多条
  不同位置的文案** —— 那是「一条 item 内多段文字」的模型，留给后续；
- 样式是三套模板（白字黑边带底 / 黄字黑边 / 无底纯描边），不做任意配色。
