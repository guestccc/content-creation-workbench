# 一键换背景（图片抠图合成）设计说明

这份文档说明工作台「图文二创 → 一键换背景」背后的算法与取舍：
它为什么只对某一类图有效、五步算术各自在堵什么漏、「高级设置」里每个参数
该在什么时候动，以及「没有子进程」这件事带来的一串运维语义。

日常使用不必看这里 —— 在网页上选一批原图、选一张背景、点「开始换背景」即可，
页面上的参数默认值就是推荐值。本文是当你想知道「为什么这么设计」时的参考。

> 实现位置：算法 `backend/app/services/cutout.py`（纯函数，移植自
> `去掉背景/抠图.py`）、执行器 `backend/app/services/background_runner.py`、
> 状态机 `backend/app/services/background_job_service.py`、
> 接口 `backend/app/api/v1/background_jobs.py`、
> 前端 `frontend/src/pages/BackgroundSwap/`。

---

## 1. 它做什么

三个输入、一个产物：

| 输入 | 说明 |
| --- | --- |
| 原图目录 + 勾选 | 扫一个目录、按缩略图勾选要处理的若干张；**不勾选 = 全部** |
| 背景图 | 一次任务只用一张，整批共用 |
| 输出目录 | 留空则落到 `materials/background/` |

产物：每张原图对应一张 PNG，文件名取原图的 stem（`羊1.jpg` → `羊1.png`、
`羊1.png` → `羊1.png`），重名时加 `-2`/`-3`；每次任务一个
`background-<时间戳>/` 子目录。

处理链是「抠出深色线条 → 统一成墨色 → 贴到背景上」。贴合有一条不变量：
**永不裁边** —— 贴上去的永远是整幅原图画布（含透明留白），笔画在画布里的位置跟它
在原图里一模一样。默认把整幅画布缩到**背景宽的 80%**、居中粘贴；留空「缩放比例」
则按原尺寸原位置贴。

脚本的默认是「原尺寸粘贴」，这里改成 0.8 是因为原尺寸贴在大背景上只占三成宽、
画面太空（见第 5 节）。**注意缩放的是整幅画布，不是裁到笔画再缩** —— 早先版本是
后者，笔画在画布里的位置整个丢失，缩完的贴纸被笔画撑满。要原尺寸原位置贴，把
「缩放比例」清空即可。

### 原图还有第二种来路：素材抓取的产物

素材抓取的一条笔记，图片本来就落在同一个目录里
（`<抓取任务输出目录>/<平台>/images/<笔记 id>/`），正好对上这边「一个目录 + 一批
文件名」的形态，所以整批带过去并预先勾好，落地后只剩「选背景图」这一件事。
两个入口，选中的都是**一条笔记的一批图**：

| 入口 | 在哪 | 怎么走 |
| --- | --- | --- |
| 结果弹窗的「换背景」 | 素材抓取 → 历史「查看」→ 结果弹窗的笔记行 | 点一下直接跳过来，目录与勾选已经填好 |
| 「从素材抓取选图」 | 本页「原图目录」下面 | 弹窗里先选一条抓取任务、再选一条笔记 |

第二个入口不是重复建设：抓取产物落在**分层目录**里，而本页的目录选择器不递归
（换背景是「挑一批图批量处理」，用户勾的就是眼前这一层），手动点进去看不到图 ——
没有这个入口，这类原图只能靠第一个入口那条单向通道带进来。

带进来的勾选只在**进入页面那一刻**（或在弹窗里选中一条笔记那一刻）生效：
自己重选目录就按普通流程走，那段「已从……带入」的说明也一并消失。
没下载到本地图片的笔记（媒体下载未开启，或该平台无法按笔记关联图片），抓取那边
的「换背景」按钮是灰的（灰色比「点了没反应」诚实），本页的选图弹窗里也根本不列它。

⚠️ 从素材抓取带过来的是**笔记配图**，多数是普通照片，而本功能只对浅底深色线条有效
（见第 2 节）—— 带得进来不等于适合处理，走这条路的一般是抓回来的手绘 / 线稿素材。

### 来源记在任务上（弱关联）

建任务时若这批图是从抓取结果带过来的，会把来源 `(source_crawl_job_id,
source_crawl_note_id)` 一起存进任务记录。它是**弱关联**：不建外键、不校验「这条
笔记是否属于该任务」、抓取记录被删也不影响本任务 —— 删抓取任务（连产物一起清）
是常规操作，不该反过来动到已经跑完的换背景产物。要的只是「回过头说得清这批图
是哪来的」。

素材抓取那边靠这对字段做反查：结果弹窗里某条笔记的图换过背景，那一行就多一个
「换背景任务 N」，点开是这些任务的简表，每行「看详情」跳回本页并直接打开那条
任务的弹窗。查法是 `GET /jobs?source_crawl_job_id=`，前端按笔记 id 分组挂到笔记行上。

## 2. 适用范围：只做「浅底 + 深色线条」

这是刻意收窄的，不是能力不足的借口。算法认的是**亮度**：纸亮、墨暗，
中间的抗锯齿像素按比例给透明度。手绘涂鸦、白板字、线稿照片都在主场。

**普通照片（人像、商品）不在适用范围**。那类图没有「纸/墨」这对前提，
要靠分割模型，不是这套算术能解决的。页面上第一天就摆了这条说明 ——
不说清的话，用户拿一张商品图跑完只会觉得「这功能是坏的」。

## 3. 五步算术，以及每一步在堵什么漏

代码本身很短，技术核心全在这五条上：

1. **不透明度 = 亮度从「纸 → 0、墨 → 1」的线性映射，绝不二值化。**
   笔画边缘的抗锯齿像素本来就是纸与墨的混合，线性映射下它们自动拿到
   0.3 / 0.6 这类中间透明度，等于白捡了边缘抗锯齿；硬阈值出来的边是啃过的，
   缩放后全是锯齿。

2. **纸纹截断** `(a - 0.08) / 0.92`。纸张纤维有 1–8% 的亮度起伏，线性映射会把
   它们全变成 3–20 的淡灰，整张图蒙一层灰。映射结果再压一道，低端直接归零。

3. **颜色统一成墨色**。边缘像素的 RGB 是被白纸「稀释」过的浅色，原样保留的话
   在白底上看没问题，一放到深色背景上就现出一圈**白边**。所以把 RGB 全换成墨芯
   均值，让「颜色」和「透明度」彻底解耦（业内叫 un-premultiply，取常量是它的
   稳健近似）。这就是「保留彩色」这个参数要关掉的东西。

4. **位置门：主体包围盒外整片置零**。背景不是纯色时（桌面木纹、阴影、纸边），
   它在亮度上会卡在纸和墨中间 —— 木纹亮度 150 上下，纸 235、墨 9，任何全局阈值
   都会给它 25% 左右的不透明度，整片木纹变成一层灰影蒙在画布上。
   **结论：分类器不可靠时，用「离主体多远」代替「像素长什么样」。**

   包围盒由「定位线」圈出来，而定位线**不能写死一个比例**：主体占画面多大取决于
   拍得多近。实测某张图的人脸在 20% 档还是 132×124，46% 档就炸成 273×570 ——
   写死的 40% 落在炸开之后，「主体」成了整幅画面，位置门随即形同虚设。
   所以默认扫一遍档位，取包围盒**炸开（面积涨 1.5 倍）前**的那一档。

5. **暖色抑制**。木纹有时就在主体旁边、位置门**里面**（矩形门框不住）。但它跟
   纸、墨在**彩度**上差着一个量级：纸 0.059、墨 0.04、木纹（含浅色木纹）0.13
   以上，中间是干净的空档。所以按彩度再压一道：超过 0.09 开始压、到 0.15 压到底。
   旁边那条保护条款是给深色笔迹的：亮度低于 `ink + 0.35×跨度` 的像素一律放行，
   深色笔迹不会因为带点颜色就被误杀；真要用彩色主体，关掉「暖色抑制」。

阈值不是拍脑袋定的：原脚本的 `--check` 会打印「不同暗度档位下的包围盒」和
「暖色抑制能抠掉多少像素」，前者定定位线，后者定彩度带。这些数字现在作为
**诊断信息**随每张产物一起返回，在页面上点开行就能看到（见第 6 节）。

## 4. 「高级设置」里每个参数在调什么

默认值 = 脚本默认 = 推荐值，**两处例外**：缩放比例默认 0.8（脚本的默认是「原尺寸」）；
校准红框是脚本里没有、本服务自加的开关。折叠起来不打扰。什么时候才需要动：

**贴合组**（决定贴到哪儿、多大）

| 参数 | 什么时候动 |
| --- | --- |
| 贴合位置 | 「自动找落点」会在背景的空白处（避开页眉和已有内容）落点；要严格居中就别选它 |
| 缩放比例 | 默认 0.8 = 整幅画布缩到背景宽的 80%，嫌小往上调。留空 = 原尺寸原位置贴（图跟背景差不多大时才合适） |
| 旋转角度 | 手绘拍歪了，靠它摆正，比在 PS 里转一遍省事 |
| 不透明度 | 想让线条「压」进背景（做旧、做水印感）时调低 |
| 自动落点起点 | 只在「自动找落点」时生效：落点太靠上会贴到背景的页眉上 |
| 离边距离 | 贴上去的整幅画布离背景边缘至少留多少像素 |
| 校准红框 | 核对「贴了多大、落在哪」时打开：给画布描一圈 2px 红边再贴。永不裁边，所以红框恒等于整幅画布的实际边界 |

**抠图组**（决定怎么抠）

| 参数 | 什么时候动 |
| --- | --- |
| 纸的透明线 | 纸偏灰（阴影里的纸）时调低，否则整片判成「不是纸」而留下灰底 |
| 墨的实心线 | 铅笔稿这类「墨不够黑」的图调高，让浅笔画也拿到不透明度；必须小于透明线 |
| 主体定位线 | 留空 = 自动扫档位。**背景被圈进主体时手动指定**，这是最常用的救急参数 |
| 纸纹截断 | 产物整张蒙雾时调高；纸很干净、线条很淡时调低 |
| 位置门 | 背景不是纯色时**必须开**；背景纯白且图占满画面时可以关 |
| 位置门扩边 | 主体边缘被切掉一细条时调大 |
| 暖色抑制 | 主体旁有木纹/暖色桌面时**必须开**；要贴彩色主体时关 |
| 保留彩色 | 默认统一成墨色。**只有**要贴彩色主体时才打开（代价是深色背景上一圈白边） |

## 5. 两处刻意改掉的行为

### 永不裁边

贴上去的永远是**整幅原图画布**（含透明留白），笔画在画布里的位置跟它在原图里
一模一样。「缩放比例」缩的是整幅画布 —— 四边到笔画的距离按同一比例一起缩，
位置信息全程保真。

早先的版本不是这样：它先把贴纸裁到笔画的包围盒再缩放，笔画在画布里的位置整个
丢失，缩完的贴纸被笔画撑满 —— 成品看着「满了」，构图却已经是另一张。
`test_cutout.py` 里有一条专门钉住这件事的回归用例。

### 贴不下就报错，不裁

脚本在「贴纸比背景大」时只 `print` 一句警告就照样裁掉 —— 批量场景下这是
**静默降质**：用户拿到一批缺角的图，还不知道是自己选错了背景。

本功能改为**该张判失败**，文案写明「抠出的图 1080×1440 比背景 800×600 大，
贴上去会被裁掉；请设置缩放比例，或换一张更大的背景」。宁可报错，也不默默切掉
用户的内容。

配套的默认值是 0.8：脚本的默认（原尺寸）会让手绘原图在大背景上只占三成宽，
画面太空。要注意 0.8 只在**宽度**上保证放得下（0.8 < 1），**高度仍由两张图的长宽比
决定** —— 竖着的画布贴到扁背景上照样会超，那时报错就是唯一的出路。所以这条报错
是兜底而不是死路：默认值覆盖面够大，越界时用户改一个数就能过。

## 6. 诊断信息：这个算法的失败模式看不出来

「定位线把背景圈进来了」「整张蒙了一层雾」这两种失败，**光看产物 PNG 很难判定**
（尤其背景本身就有纹理时）。原脚本的 `--check` 就是为此存在的，本功能把它
保下来了：每张图的 `stats` 里带纸色/墨色/亮度跨度、定位线落在哪一档及是否炸开、
位置门扩边像素、暖色抑制抠掉多少像素、可见像素占比等。

页面上的呈现分两层：表格「诊断」列默认只显示可见占比或有几条提示，
点开行才摊开全部数字。异常情况（跨度 < 40、包围盒占画面一半以上）会在
`warnings` 里直接以 `Tag color="warning"` 顶出来，并**默认展开那一行** ——
有提示的时候正是要看数字的时候。

## 7. 「没有子进程」带来的一串语义

与镜头分割、字幕提取、一键成品不同，**抠图是纯 numpy 运算，跑在 worker 线程
自己的进程里**，没有子进程。由此派生四条必须写明的语义：

1. **取消不是即时的。** 没有子进程可杀，能做的只是「等这一张算完再收手」，
   所以**取消延迟的上界 = 单张图的处理时间**（大图上可能是十几秒）。这不是实现
   偷懒，是算法形态决定的 —— 页面上的停止确认框如实写了这一点，别让用户以为
   点了没反应。
2. **数据库里没有 `child_pid` 列**，重启回收也不需要核对进程身份。
3. **没有退出码可交叉验证**，判成功的依据只有「本张无异常 + 产物文件存在且非空」。
4. **单实例部署的前提**：`recover_interrupted_jobs()` 只看状态列，认不出「这条
   running 是别的进程正在跑的」。两个后端进程共用一个 db 时，后启动的会把前一个
   正在跑的任务判成 failed。本项目是单机单实例工具（`HOST` 固定 `127.0.0.1`），
   不构成实际问题。

取消时剩余图片标 `skipped`，因服务停止而中断的那条判 `failed` 且原因写
「服务停止或重启，任务中断（可直接重新发起）」—— 两种原因**混着写**会让用户
以为是自己点的取消。

### 尺寸闸门

算法在 worker 线程里跑，**没有子进程隔离**，一张 48MP 的图能吃 1.5–2GB、
把整个 uvicorn 连同其它 worker 一起带走。所以有 `BACKGROUND_MAX_PIXELS`
（默认 3000 万像素）：`Image.open()` 后立刻读 `im.size`（读 size 不解码，几乎零成本），
超限**当下就把这一条判 failed**，文案带上实际尺寸与上限（「原图是 8000×6000
（4800 万像素），超过单张上限 3000 万像素；请先缩放再处理」），不等算到一半。

### 落盘

产物用**临时文件 + `Path.replace()` 原子替换**写出去，避免硬退出时留下半截 PNG
—— 进程结束时的有界等待只有 3 秒（`BACKGROUND_STOP_GRACE_SECONDS`），不够写完
一张大图是很正常的事。

## 8. 接口与产物路径

prefix `/background`：

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/jobs` | 创建任务并入队（可带 `source_crawl_job_id` / `source_crawl_note_id`） |
| GET | `/jobs` | 分页列表；`?source_crawl_job_id=` 只列出来自该抓取任务的那些 |
| GET | `/jobs/{id}` | 任务详情（含每张图的条目） |
| GET | `/jobs/{id}/items/{n}/output` | 第 n 张的产物 PNG |
| POST | `/jobs/{id}/cancel` | 取消 |
| PUT | `/jobs/{id}/remark` | 改备注 |
| DELETE | `/jobs/{id}?purge_files=` | 删任务（可选连产物一起清） |
| POST | `/jobs/batch-delete` | 批量删 |

两条安全不变量：

- **产物只由任务记录推导**。产物端点只收「任务 id + 序号」，不收路径，序号越界
  直接 404 —— 产物**不走** `/fs/preview`（那条路能读任意绝对路径，是给素材预览用的）。
- **`files` 只接受纯文件名**，带路径分隔符一律 400。勾选清单来自前端，但校验必须
  在后端：否则一个 `../../` 就能让任务去处理目录外的文件。

创建时**一次性查完能查的错**（背景图在不在、原图清单是否为空、输出目录能不能建），
用户点击那一刻就知道问题，而不是排队几分钟后整条失败。

## 9. 已知但不在本次修的风险

SQLite 连接池是 `QueuePool(5, max_overflow=10)`，5 个 worker 各持一个连接 +
FastAPI 请求线程，理论上限 15 已经被现有代码撑到过。加第 6 个 worker（本功能）
会让它更靠近上限 —— 这是既有风险，不是本功能引入的。真出现 `QueuePool limit`
报错时，修法是给 `create_engine` 显式放大 `pool_size`。
